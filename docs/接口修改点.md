# lobeai 对外接口文档（接口变更说明）

> 本文档面向**对接开发方**，说明 lobeai 对外接口的变更与当前契约。
> 近期变更：2026-09-07（新增管理员邀请统计与套利排查 `POST /api/admin/invite/stats`，见 §5；server_b 新增 `/internal/invite/group-lookup`，见 §5.4）

---

## 1. 充值/额度聚合接口 — update-user-quota

返回用户在各套餐下的额度情况，统一人民币计价，按套餐类型打包为列表，便于后续扩展新套餐。

> **背景**：旧的多套餐按月付费体系已下线，当前仅保留 **claude code** 套餐（预付费 / 按量）。

### 1.1 请求

```
POST /api/update-user-quota
Content-Type: application/json
```

请求体：

```json
{
  "username": "张三",
  "email": "user@x.com"
}
```

| 字段         | 类型   | 必填 | 说明                                                        |
| ------------ | ------ | ---- | ----------------------------------------------------------- |
| `username` | string | 是   | 用户名。当前**不参与计算**，仅保留字段                |
| `email`    | string | 是   | 用户邮箱，格式需合法（EmailStr 校验）。**唯一判定键** |

### 1.2 响应

额度按套餐类型打包为 **`plans` 列表**（未来新增套餐时通知对接方追加一项）。

```json
{
  "email": "user@x.com",
  "currency": "CNY",
  "plans": [
    {
      "type": "claude code",
      "balance": 12.34,
      "total_recharged": 50.00,
      "unlimited": false,
      "has_key": true,
      "balance_warning": { "enabled": false, "message": null }
    }
  ]
}
```

#### 字段说明

| 字段                        | 类型   | 说明                                                                                                  |
| --------------------------- | ------ | ----------------------------------------------------------------------------------------------------- |
| `email`                   | string | 用户邮箱                                                                                              |
| `currency`                | string | 币种，固定`"CNY"`（人民币口径）                                                                     |
| `plans`                   | array  | 套餐额度列表，每项一个套餐                                                                            |
| `plans[].type`            | string | 套餐类型，当前仅`"claude code"`                                                                     |
| `plans[].balance`         | number | **剩余可用余额 ¥**                                                                             |
| `plans[].total_recharged` | number | **该套餐累计充值 ¥**                                                                           |
| `plans[].unlimited`       | bool   | 是否无限额度。为`true` 时 `balance` 恒为 `0.0`，**以本标志为准**                          |
| `plans[].has_key`         | bool   | 该用户该套餐是否已开通（存在可用额度账户）                                                            |
| `plans[].balance_warning` | object | **低余额警告**。`enabled: true` 时 `message` 为提示文案，展示方应弹提示；`false` 时不警告 |

### 1.3 边界行为

| 场景                            | 表现                                                                                      |
| ------------------------------- | ----------------------------------------------------------------------------------------- |
| 用户未开通该套餐                | `has_key: false`，`balance: 0.0`                                                      |
| 用户为无限额度                  | `balance: 0.0` + `unlimited: true`（展示方应显示「无限」）                            |
| 额度数据暂不可用 / 未开通       | 优雅返回`has_key: false`、`balance: 0.0`，**不返回错误**                        |
| 汇率数据暂不可用                | 金额按`0.0` 处理，不影响接口可用性                                                      |
| 未知的套餐`type`              | 返回全 0 占位记录，接口不报错                                                             |
| 余额低于低余额阈值（默认 2 元） | `balance_warning.enabled: true`，`message` 为提示文案，**对接方应展示充值提示** |
| 余额充足 / 无限额度 / 未开通    | `balance_warning.enabled: false`，`message: null`，无需提示                           |
| server_b 额度服务暂不可用       | `balance_warning.enabled: false`，接口正常返回                                          |

## 2. 管理员激活码统计 — activation-codes/stats

管理员查询激活码批次统计（按套餐 + 有效期 + 面额分组）。**本次变更：每个批次新增人民币面额 `quota_rmb` 字段**，原 `quota`（额度）字段保留不变。

### 2.1 请求

```
POST /api/admin/activation-codes/stats
```

> 需要管理员认证（管理员账号密码）。

### 2.2 响应

**变更前**：

```json
{
  "plan_level": "claude code",
  "days": 0,
  "quota": 737463,
  "total": 4,
  "used": 4,
  "available": 0
}
```

**变更后**（新增 `quota_rmb`）：

```json
{
  "plan_level": "claude code",
  "days": 0,
  "quota": 737463,
  "quota_rmb": 9.99,
  "total": 4,
  "used": 4,
  "available": 0
}
```

顶层另有 `summary` 汇总（`total` / `used` / `available` 数量），本次不变。

#### 字段说明

| 字段           | 类型   | 说明                                  |
| -------------- | ------ | ------------------------------------- |
| `plan_level` | string | 套餐类型                              |
| `days`       | number | 有效期（天），`0` 表示永久有效      |
| `quota`      | number | 该批次激活码的额度                    |
| `quota_rmb`  | number | **该批次激活码的人民币面额 ¥** |
| `total`      | number | 该批次激活码总数                      |
| `used`       | number | 已使用数                              |
| `available`  | number | 可用数（= total - used）              |

### 2.3 对接方注意

- 展示人民币面额时取 **`quota_rmb`**（已取整为整数）；展示额度原值用 `quota`。
- 若接口部署的是老版本（尚无 `quota_rmb` 字段），前端应做容错：字段缺失时回退显示 `quota`。
- **按取整价格合并**：汇率波动导致同一取整价格（`quota_rmb`）下原始 `quota` 有微小差异的多批激活码，会合并为一行，`total`/`used`/`available` 为该价格下多批之和，`quota` 显示其中任意一个原始值。

## 3. 平台套餐用量统计 — usage-summary

管理员查看平台全部套餐的**累计充值、累计消耗**，支持按自然月 / 自然周汇总。统一人民币口径。

### 3.1 请求

```
POST /api/admin/usage-summary
```

需要管理员认证（管理员账号密码）。

请求体：

```json
{
  "username": "admin",
  "password": "***",
  "granularity": "month"
}
```

| 字段            | 类型   | 必填 | 说明                                                                                                       |
| --------------- | ------ | ---- | ---------------------------------------------------------------------------------------------------------- |
| `username`    | string | 是   | 管理员用户名                                                                                               |
| `password`    | string | 是   | 管理员密码                                                                                                 |
| `granularity` | string | 否   | 汇总粒度：`""`（仅累计）/ `"month"`（按自然月）/ `"week"`（按自然周，周一为一周起点）。缺省为 `""` |

### 3.2 响应

`granularity=""` 时（仅累计）：

```json
{
  "currency": "CNY",
  "summary": {
    "total_recharged": 1234.56,
    "total_consumed": 789.12
  },
  "by_plan": [
    {
      "type": "api",
      "total_recharged": 500.00,
      "total_consumed": 300.10
    },
    {
      "type": "claude code",
      "total_recharged": 734.56,
      "total_consumed": 489.02
    }
  ]
}
```

`granularity="month"` 时，额外返回 `by_month` 列表；`granularity="week"` 时，额外返回 `by_week` 列表（键名不同，结构相同）：

```json
{
  "currency": "CNY",
  "summary": { "...": "同上" },
  "by_plan": [ "...": "同上" ],
  "by_month": [
    {
      "bucket": "2026-07",
      "recharged": 800.00,
      "consumed": 400.50
    }
  ]
}
```

#### 字段说明

| 字段                                               | 类型   | 说明                                                   |
| -------------------------------------------------- | ------ | ------------------------------------------------------ |
| `currency`                                       | string | 币种，固定`"CNY"`（人民币口径）                      |
| `summary.total_recharged`                        | number | 全部套餐累计充值 ¥                                    |
| `summary.total_consumed`                         | number | 全部套餐累计消耗 ¥                                    |
| `by_plan[].type`                                 | string | 套餐类型：`"api"` / `"claude code"`                |
| `by_plan[].total_recharged`                      | number | 该套餐累计充值 ¥                                      |
| `by_plan[].total_consumed`                       | number | 该套餐累计消耗 ¥                                      |
| `by_month[]` / `by_week[]`                     | array  | 分桶汇总（仅当`granularity` 指定时返回），按时间升序 |
| `by_month[].bucket`                              | string | 月份，`YYYY-MM`                                      |
| `by_week[].bucket`                               | string | 自然周起点日期，`YYYY-MM-DD`（周一）                 |
| `by_month[].recharged` / `by_week[].recharged` | number | 该桶充值 ¥                                            |
| `by_month[].consumed` / `by_week[].consumed`   | number | 该桶消耗 ¥                                            |

### 3.3 统计口径（对接方须知，2026-09-02 邀请假收入已剔除）

- **api 套餐**：充值 = 生成的 key 额度（**key 一经生成即计入充值**）；消耗 = 实际使用量。
- **claude code 套餐**：充值 = **已激活**的激活码面额之和（未激活的不计）**- 邀请返利假收入**（`claude_agent.invite_rewards.reward_quota` 按 `quota→RMB` 原值扣除，分桶维度同 `created_at` 分桶扣除）；消耗 = 实际使用量。
- **排除名单**：平台维护一份排除邮箱名单，名单内邮箱的 claude code 用量**不计入统计**（当前仅 claude code 套餐生效，api 套餐不受影响）。名单内容由平台运营侧维护，对接方无需关心其来源。
- **消耗不含退款**：按原始用量累计，退款/补偿不做扣减。
- **邀请返利不计入**：`a邀b` 产生的 `10%` 返利额度通过 `server_b` 直接累加 `tokens`，属于假收入，`usage-summary` 已在 `claude code` 的充值侧按 `quota` 原值扣除（累计与 `by_month`/`by_week` 均扣除），运营报表不含该部分。
- 所有金额均以人民币（¥）返回，保留两位小数。

### 3.4 边界行为

| 场景                     | 表现                                        |
| ------------------------ | ------------------------------------------- |
| `granularity` 传非法值 | 按`""` 处理（仅返回累计，不返回分桶）     |
| 某套餐暂无数据           | 该套餐充值/消耗返回`0.0`，接口正常        |
| 统计数据源暂不可用       | 对应套餐充值/消耗按`0.0` 返回，接口不报错 |

## 4. 邀请系统 — 复用 new-api 邀请码 + 自建返利（2026-09-02）

> 背景：邀请码验真直接复用 `oneapi.users.aff_code`（只读），返利逻辑由 `claude_agent` 自建；`invite_bindings` / `invite_rewards` 落 `claude_agent` 库。所有涉 `server_b` 操作必须过 `server_b` HTTP。

### 4.1 注册接口新增邀请码字段 — `POST /api/register`

**变更**：请求体新增可选字段 `aff_code`，服务端前置校验 `services/InviteService.validate_invite`，失败直接拒注册；成功则透传给 `new-api` 写 `users.inviter_id`，并在 `claude_agent.invite_bindings` 落库。

请求（新增 `aff_code`）：

```json
{
  "username": "张三",
  "password": "***",
  "email": "new_user@x.com",
  "verification_code": "123456",
  "aff_code": "YRvr"
}
```

| 字段         | 类型   | 必填 | 说明                                                          |
| ------------ | ------ | ---- | ------------------------------------------------------------- |
| `aff_code` | string | 否   | 邀请码（`oneapi.users.aff_code`，4位）。不传/空串表示无邀请 |

校验规则（任一失败返回 `success:false` + `message`）：

| 场景                                                                                                | `message`                                |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 邀请码不存在                                                                                        | `邀请码不存在`                           |
| 自己邀请自己（`aff_code` 所属邮箱 == 被邀邮箱）                                                   | `不能邀请自己`                           |
| 该账号已绑定过邀请人（`invite_bindings` 唯一或 `users.inviter_id !=0`）                         | `该账号已绑定邀请人，不能重复绑定`       |
| 老用户补填（`users_center` 已存在或非新用户）                                                     | `仅新用户可使用邀请码，老用户不能补填`   |
| 邀请者自身未充值（走`server_b GET /billing/balance` 同口径，无 `has_key` / `total_quota==0`） | `邀请您的邀请者自身没有充值，邀请码无效` |

成功：注册流程不变，额外写入一条 `invite_bindings(inviter_user_id, inviter_email, invitee_user_id, invitee_email, aff_code)`。

### 4.2 新增邀请查询接口 — `POST /api/invite/info`（一站式，`code`/`rewards` 已删除）

均无需鉴权，`EmailStr` 校验。原 `POST /api/invite/code`、`POST /api/invite/rewards` 已删除合并入 `info`，请统一使用 `info`。

#### 4.2.1 一站式 — `POST /api/invite/info`

`code + rewards` 合并，字段为两者并集：

```json
{
  "success": true,
  "data": {
    "email": "user@x.com",
    "aff_code": "YRvr",
    "invite_count": 2,
    "total_reward_rmb": 21.0,
    "total_reward_quota": 1557864,
    "rewards": [ "...同上..." ]
  }
}
```

### 4.3 额度聚合接口 `POST /api/update-user-quota` — 保持原状

**本次不改**：应需求恢复原状，**不额外返回 `invite`**，保持 `{"email","currency","plans[]"}` 原契约。对接方需要邀请信息请调 `POST /api/invite/info`（`§4.2`）。

### 4.4 激活码兑换触发返利 — `POST /api/random-activation-code`

**变更**：`mark_as_used` 后若被兑换邮箱存在 `invite_bindings`，自动计算并到账返利。

- 口径：`激活码面额 quota → RMB`（`RMB = quota / 500000 * USD汇率`，汇率同 `update-user-quota`），`返利 = 充值RMB * 10%`，**无封顶**（2026-09-02 起取消 20 元封顶）。
- 归属：邀请码属于谁，谁获得返利（`inviter_email`）。
- 到账：`lobeai` → `server_b POST /internal/invite/bonus {"inviter_email","quota":reward_quota,...}` 原子 `increment_token_remain_quota`（无 token 时 B 侧兜底创建）。
- 幂等：`invite_rewards (activation_code_id, binding_id)` 唯一，重复兑换不重复返利。
- 兑换响应本身不变；返利失败仅打日志，不影响 `status:true`。

### 4.5 内部接口 — `POST /internal/invite/bonus`（server_b，仅 lobeai 调用）

```
POST http://server_b:9000/internal/invite/bonus
{ "inviter_email": "a@x.com", "quota": 74184, "invitee_email": "b@x.com", "activation_code_id": "xxx" }
→ { "status": true, "quota_added": 74184, "quota_total": 814925 }
```

仅做额度累加，不做汇率/封顶计算。

### 4.6 约束汇总

- 返利仅 `claude code` 激活码兑换时触发；其它 `plan_level` 兑换直接拒。
- 一个账号只能被邀请一次、必须新用户、不允许自邀。
- 邀请者必须已充值（`server_b /billing/balance` 同口径）。
- `token Name = "Claude Code - "+ email` 受 `new-api` 50 字符限制，**被邀邮箱需 <36 字符**，否则 `create_token` 报 `Token name is too long`（兑换失败、码不消耗）。

## 5. 邀请统计 + 套利排查 — `POST /api/admin/invite/stats`（2026-09-07）

> 背景：上线 4 天内两单真实邀请均为**小号套利**（自充自邀拿 10% 返利）。
> 本接口一次性输出：①被邀请人数 ②累计返利 ③按 IP 交集识别套利疑似 ④核对套利人 B 端 token 分组是否已挪 `backup`（高倍率组，抑制返利套现）。
> 实现：`services/InviteStats.py`；只读，不写任何库。

### 5.1 请求

```
POST /api/admin/invite/stats
Content-Type: application/json
```

> 需要管理员认证（同 `usage-summary`，`Depends(get_admin_client)`）。

请求体：

```json
{
  "include_excluded": false
}
```

| 字段                | 类型 | 必填 | 说明                                                                 |
| ------------------- | ---- | ---- | -------------------------------------------------------------------- |
| `include_excluded` | bool | 否   | 是否带出**排除名单**（`data/excluded_emails.json`，测试号等）的绑定。缺省 `false`，名单内 inviter/invitee 的绑定整条跳过 |

### 5.2 响应

```json
{
  "status": true,
  "summary": {
    "inviter_count": 2,
    "binding_count": 2,
    "arbitrage_suspected_count": 2,
    "unprocessed_arbitrage_count": 2,
    "total_reward_rmb": 10.97
  },
  "inviters": [
    {
      "inviter_email": "jackzhangwg@gmail.com",
      "invitee_count": 1,
      "invitees": [
        {
          "email": "gojackzhang@qq.com",
          "aff_code": "kngb",
          "bound_at": "2026-09-04T09:25:03+00:00",
          "excluded": false,
          "matched_ips": []
        }
      ],
      "reward_count": 1,
      "total_recharge_quota": 7396449,
      "total_recharge_rmb": 99.7,
      "total_reward_quota": 739614,
      "total_reward_rmb": 9.97,
      "arbitrage_suspected": true,
      "matched_ips": ["240e:390:a2e2:..."],
      "excluded": false,
      "token_group": "claude code",
      "is_backup_group": false,
      "unprocessed_arbitrage": true,
      "token_missing": false,
      "b_remain_quota": 769049,
      "b_used_quota": 8096830
    }
  ]
}
```

#### 字段说明

| 字段                                | 类型    | 说明                                                                     |
| ----------------------------------- | ------- | ------------------------------------------------------------------------ |
| `summary.inviter_count`           | number  | 邀请人数（排除名单过滤后）                                             |
| `summary.binding_count`           | number  | 邀请绑定总条数                                                          |
| `summary.arbitrage_suspected_count` | number | 套利疑似邀请人数（IP 交集≠空）                                        |
| `summary.unprocessed_arbitrage_count` | number | **未处理套利人数**（疑似 且 token 分组≠`backup`）                |
| `summary.total_reward_rmb`        | number  | 返利总额 ¥（排除名单过滤后）                                          |
| `inviters[].invitee_count`        | number  | 被邀请人数                                                              |
| `inviters[].invitees[].matched_ips` | array  | 该被邀请人与邀请人的重合 IP 列表                                       |
| `inviters[].reward_count`         | number  | 返利笔数（`invite_rewards` 行数）                                    |
| `inviters[].total_recharge_rmb`   | number  | 被邀请人累计充值 ¥（激活码面额口径）                                |
| `inviters[].total_reward_rmb`     | number  | 累计返利 ¥                                                             |
| `inviters[].arbitrage_suspected`  | bool    | **套利疑似**：双方全量历史登录 IP（`user_sessions` v4+v6）交集≠空 |
| `inviters[].token_group`          | string  | B 端 token 当前分组（如 `claude code` / `backup`）                 |
| `inviters[].is_backup_group`      | bool    | `token_group == "backup"`，true = 已处理（高倍率组生效）           |
| `inviters[].unprocessed_arbitrage` | bool    | **未处理套利**：疑似 且 非backup 分组                               |
| `inviters[].b_remain_quota` / `b_used_quota` | number | B 端 token 剩余/已用额度（辅助核对）                            |

### 5.3 判定口径

- **IP 交集判定（宽松）**：邀请人与被邀请人各自的**全部历史登录 IP**（`claude_agent.user_sessions` 的 `ip_v4`/`ip_v6`，空值剔除）求交集，非空即 `arbitrage_suspected=true`。不做注册时点严格判定。
- **分组判定**：token 分组是管理员手动处置的标记——把套利人 token 挪进 `backup` 分组（倍率更高、消耗更快，抑制返利套现）视为"已处理"。`token_group != 'backup'` 即 `unprocessed_arbitrage=true`。
- **排除名单**：复用 `data/excluded_emails.json`（与 `usage-summary` 同一份），inviter 或 invitee 命中即该绑定标 `excluded`，默认跳过（不参与统计与判定）。

### 5.4 依赖的 server_b 内部接口 — `GET /internal/invite/group-lookup`

```
GET http://server_b:9000/internal/invite/group-lookup?email=a@x.com
→ { "status": true, "email": "a@x.com", "token_exists": true,
    "token_id": 114, "token_group": "claude code",
    "remain_quota": 769049, "used_quota": 8096830 }
```

- 查 B 端 `oneapi.tokens`（`name = "Claude Code - <email>"`）的 **`group` 字段**；token 不存在 → `token_exists:false, token_group:null`。
- 实现于 server_b `db_client.find_token_group_by_name`；与渠道（`channels` 表/消费路由）**无关**——分组是 token 自身属性，充值即有。
- 鉴权同 `/internal/invite/bonus`：靠 cloudflared tunnel + CF Service Token，无本地鉴权。

### 5.5 边界行为

| 场景                                  | 表现                                                                   |
| ------------------------------------- | ---------------------------------------------------------------------- |
| 邀请人 B 端无 token                   | `token_missing=true`，不参与分组判定（正常不会发生：有返利必有 token） |
| server_b group-lookup 调用失败        | `token_group_status="lookup_error"`，该人不计入未处理数            |
| 疑似但已挪 `backup` 分组             | `is_backup_group=true`，`unprocessed_arbitrage=false`                |
| 双方 `user_sessions` 均无 IP 记录     | 交集为空，不判疑似                                                     |
| 排除名单内的绑定                      | 默认整条跳过；`include_excluded=true` 时带出且标 `excluded`          |
