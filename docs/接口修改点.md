# lobeai 对外接口文档（接口变更说明）

> 本文档面向**对接开发方**，说明 lobeai 对外接口的变更与当前契约。
> 近期变更：2026-08-02

---

## 1. 充值/额度聚合接口 — update-user-quota

返回用户在各套餐下的额度情况，统一人民币计价，按套餐类型打包为列表，便于后续扩展新套餐。

> **背景**：旧的多套餐按月付费体系已下线，当前仅保留 **claude code** 套餐（预付费 / 按量）。

### 1.1 请求

```
POST /api/update-user-quota
Content-Type: application/json
```

请求体：

```json
{
  "username": "张三",
  "email": "user@x.com"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名。当前**不参与计算**，仅保留字段 |
| `email` | string | 是 | 用户邮箱，格式需合法（EmailStr 校验）。**唯一判定键** |

### 1.2 响应

额度按套餐类型打包为 **`plans` 列表**（未来新增套餐时通知对接方追加一项）。

```json
{
  "email": "user@x.com",
  "currency": "CNY",
  "plans": [
    {
      "type": "claude code",
      "balance": 12.34,
      "total_recharged": 50.00,
      "unlimited": false,
      "has_key": true
    }
  ]
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `email` | string | 用户邮箱 |
| `currency` | string | 币种，固定 `"CNY"`（人民币口径） |
| `plans` | array | 套餐额度列表，每项一个套餐 |
| `plans[].type` | string | 套餐类型，当前仅 `"claude code"` |
| `plans[].balance` | number | **剩余可用余额 ¥** |
| `plans[].total_recharged` | number | **该套餐累计充值 ¥** |
| `plans[].unlimited` | bool | 是否无限额度。为 `true` 时 `balance` 恒为 `0.0`，**以本标志为准** |
| `plans[].has_key` | bool | 该用户该套餐是否已开通（存在可用额度账户） |

### 1.3 边界行为

| 场景 | 表现 |
|---|---|
| 用户未开通该套餐 | `has_key: false`，`balance: 0.0` |
| 用户为无限额度 | `balance: 0.0` + `unlimited: true`（展示方应显示「无限」） |
| 额度数据暂不可用 / 未开通 | 优雅返回 `has_key: false`、`balance: 0.0`，**不返回错误** |
| 汇率数据暂不可用 | 金额按 `0.0` 处理，不影响接口可用性 |
| 未知的套餐 `type` | 返回全 0 占位记录，接口不报错 |

## 2. 管理员激活码统计 — activation-codes/stats

管理员查询激活码批次统计（按套餐 + 有效期 + 面额分组）。**本次变更：每个批次新增人民币面额 `quota_rmb` 字段**，原 `quota`（额度）字段保留不变。

### 2.1 请求

```
POST /api/admin/activation-codes/stats
```

> 需要管理员认证（管理员账号密码）。

### 2.2 响应

**变更前**：
```json
{
  "plan_level": "claude code",
  "days": 0,
  "quota": 737463,
  "total": 4,
  "used": 4,
  "available": 0
}
```

**变更后**（新增 `quota_rmb`）：
```json
{
  "plan_level": "claude code",
  "days": 0,
  "quota": 737463,
  "quota_rmb": 9.99,
  "total": 4,
  "used": 4,
  "available": 0
}
```

顶层另有 `summary` 汇总（`total` / `used` / `available` 数量），本次不变。

#### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `plan_level` | string | 套餐类型 |
| `days` | number | 有效期（天），`0` 表示永久有效 |
| `quota` | number | 该批次激活码的额度 |
| `quota_rmb` | number | **该批次激活码的人民币面额 ¥（本次新增）** |
| `total` | number | 该批次激活码总数 |
| `used` | number | 已使用数 |
| `available` | number | 可用数（= total - used） |

### 2.3 对接方注意

- 展示人民币面额时取 **`quota_rmb`**（已取整为整数）；展示额度原值用 `quota`。
- 若接口部署的是老版本（尚无 `quota_rmb` 字段），前端应做容错：字段缺失时回退显示 `quota`。
- **按取整价格合并**：汇率波动导致同一取整价格（`quota_rmb`）下原始 `quota` 有微小差异的多批激活码，会合并为一行，`total`/`used`/`available` 为该价格下多批之和，`quota` 显示其中任意一个原始值。

## 3. 平台套餐用量统计 — usage-summary（本次新增）

管理员查看平台全部套餐的**累计充值、累计消耗**，支持按自然月 / 自然周汇总。统一人民币口径。

### 3.1 请求

```
POST /api/admin/usage-summary
```

需要管理员认证（管理员账号密码）。

请求体：

```json
{
  "username": "admin",
  "password": "***",
  "granularity": "month"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 管理员用户名 |
| `password` | string | 是 | 管理员密码 |
| `granularity` | string | 否 | 汇总粒度：`""`（仅累计）/ `"month"`（按自然月）/ `"week"`（按自然周，周一为一周起点）。缺省为 `""` |

### 3.2 响应

`granularity=""` 时（仅累计）：

```json
{
  "currency": "CNY",
  "summary": {
    "total_recharged": 1234.56,
    "total_consumed": 789.12
  },
  "by_plan": [
    {
      "type": "api",
      "total_recharged": 500.00,
      "total_consumed": 300.10
    },
    {
      "type": "claude code",
      "total_recharged": 734.56,
      "total_consumed": 489.02
    }
  ]
}
```

`granularity="month"` 时，额外返回 `by_month` 列表；`granularity="week"` 时，额外返回 `by_week` 列表（键名不同，结构相同）：

```json
{
  "currency": "CNY",
  "summary": { "...": "同上" },
  "by_plan": [ "...": "同上" ],
  "by_month": [
    {
      "bucket": "2026-07",
      "recharged": 800.00,
      "consumed": 400.50
    }
  ]
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `currency` | string | 币种，固定 `"CNY"`（人民币口径） |
| `summary.total_recharged` | number | 全部套餐累计充值 ¥ |
| `summary.total_consumed` | number | 全部套餐累计消耗 ¥ |
| `by_plan[].type` | string | 套餐类型：`"api"` / `"claude code"` |
| `by_plan[].total_recharged` | number | 该套餐累计充值 ¥ |
| `by_plan[].total_consumed` | number | 该套餐累计消耗 ¥ |
| `by_month[]` / `by_week[]` | array | 分桶汇总（仅当 `granularity` 指定时返回），按时间升序 |
| `by_month[].bucket` | string | 月份，`YYYY-MM` |
| `by_week[].bucket` | string | 自然周起点日期，`YYYY-MM-DD`（周一） |
| `by_month[].recharged` / `by_week[].recharged` | number | 该桶充值 ¥ |
| `by_month[].consumed` / `by_week[].consumed` | number | 该桶消耗 ¥ |

### 3.3 统计口径（对接方须知）

- **api 套餐**：充值 = 生成的 key 额度（**key 一经生成即计入充值**）；消耗 = 实际使用量。
- **claude code 套餐**：充值 = **已激活**的激活码面额之和（未激活的不计）；消耗 = 实际使用量。
- **排除名单**：平台维护一份排除邮箱名单，名单内邮箱的 claude code 用量**不计入统计**（当前仅 claude code 套餐生效，api 套餐不受影响）。名单内容由平台运营侧维护，对接方无需关心其来源。
- **消耗不含退款**：按原始用量累计，退款/补偿不做扣减。
- 所有金额均以人民币（¥）返回，保留两位小数。

### 3.4 边界行为

| 场景 | 表现 |
|---|---|
| `granularity` 传非法值 | 按 `""` 处理（仅返回累计，不返回分桶） |
| 某套餐暂无数据 | 该套餐充值/消耗返回 `0.0`，接口正常 |
| 统计数据源暂不可用 | 对应套餐充值/消耗按 `0.0` 返回，接口不报错 |
